Moon: a VS Code coding agent whose loop runs on TrueForge

Technical Abstract · TrueFoundry Forge-a-thon, Techfest 2026-27, IIT Bombay · Round 1 write-up

Team Simpletons (ID TM-EE7CC39ADE6) · Ayush Jadaun (lead), Abhay Agarwal, Akshay Yadav, Arnav Raj

Repository: https://github.com/Abhay030405/moon-vscode-extension · Demo video: Google Drive folder

Overview. Moon is a VS Code extension that turns one plain-language request into a reviewed, multi-file change. TrueForge runs the agent loop and is the only part of the system that talks to a model. Moon gives the agent its eyes and hands as MCP tools, decides what goes into the model's context, and keeps the user's files untouched until the user accepts each hunk. The agent edits a hidden copy of the project and runs the tests there. Every change then comes back through a TrueForge tool approval that opens Moon's review screen. If the main model fails, Moon restarts the same request on a backup model with no click from the user.

2  Starting point

From scratch. The first commit is 6bda597 (6 Nov 2026, "Project skeleton, docs and agent rules"). Moon is not a fork, and no upstream agent loop is kept. Forking Cline or Roo would have meant untangling their own loop and replacing most of their flow, and a small codebase is one we can explain line by line. We copied three tree-sitter tag query files from Aider (Apache-2.0, adapted from the MIT tree-sitter grammars) and took two ideas without code: Aider's ranked repo map and Continue's per-hunk Accept/Reject buttons. Each one is listed with source, link and licence in NOTICE.md.

3  Architecture on TrueForge

Moon is a pnpm monorepo with three packages (Fig. 1). packages/core holds all logic and never imports vscode, so its 154 unit tests and the evals run without an editor. packages/extension is a thin layer that wires VS Code to core, and packages/webview-ui is the React panel. TrueForge 0.184.2 runs in local mode on the same machine.

How Moon talks to TrueForge. Moon uses the TypeScript SDK. Each chat creates a session from an inline agent spec built from agents/moon-agent.json, with the model name filled in from config. Moon sends turns and reads the event stream: text deltas, tool calls, tool results, approval requests and the turn's end state. Text deltas stream to the panel and each tool call becomes one live-log line, without blocking the editor. TrueForge cannot tell a tool which session called it, so Moon serves two MCP endpoints. The inline endpoint works on the open file. The agent endpoint works on the current run's hidden copy.

Editor capabilities as MCP tools. The agent decides what to read and change; Moon only offers the tools and enforces their limits.

TrueForge approval drives the review. apply_changes is in the agent's requireApprovalForTools list. When TrueForge emits tool.approval_required for it, Moon opens the review screen: files, then hunks, with Accept all, per file and per hunk. TrueForge's answer can only be allow or deny, so Moon keeps the user's hunk choices and sends allow. The tool, running in the extension, then writes only the accepted hunks in one all-or-nothing edit with a backup. If the user rejects everything, Moon sends deny with a reason that lists the rejected hunks, and the agent reads that reason. run_command works the same way through an approval card (Allow once, Always for this exact command in this run, Deny).

Inline edit (Task A). Ctrl+I opens an instruction box under the selection. A separate agent spec (moon-inline.json) runs with five tools and an 8-step limit, and ends by calling propose_edit. Moon draws each change in the file, green new lines under red old lines, with Accept and Reject buttons above each hunk. The preview exists only in the unsaved editor text, so Stop removes it and Ctrl+Z undoes an accepted edit.

Harness features we use. The scout is a TrueForge dynamic subagent that searches in its own thread and returns at most six files with a reason each, which keeps the main agent's context small. Compaction triggers at 80% of the model's window, the same window number that sets the map budget. Deferred tool loading is on, with eight tools preloaded. ask_user_question drives the card shown after two failed fix attempts. The loop limit is 60 steps for agent mode. Code Mode and skills are not used because they need TrueForge's sandbox, which does not run on Windows, our development machine.

4  How context is selected

Flask 3.1.3 is about 17,000 lines, so the agent cannot read everything. Fig. 3 shows what Moon puts into the model's window, the budget for each part, and how the agent's file choices reach the screen. Every cap is a setting in config/moon.json.

Ranking follows Aider's repo-map idea, rewritten from scratch: tree-sitter (WebAssembly, no native build) reads definitions and references, and the PageRank start is tilted toward files that match the request. One window number sets both the map budget and TrueForge's compaction point, so the two never disagree. A large @file becomes an outline with a note to read the parts needed. We did not add embeddings: an embedding call from the extension would be a direct model call, and the index goes stale. On a held-out set of 10 Flask requests written after all tuning, the agent found 27 of 27 required files on both models. The map alone puts 66% of them in its top 10, and the scout closes the rest.

RoleModel (TrueForge name)Where it runs
MainClaude Sonnet 5.5 (anthropic/claude-sonnet-5-5)Anthropic API, TrueForge catalog provider
BackupDeepSeek V4.1 Flash (azure-deepseek/deepseek-v4-1-flash-2)Azure AI Foundry, TrueForge OpenAI-compatible provider (1,048,576-token window, 65,536 max output)

Cost per task (TrueForge usage events, list price per million input / output tokens: Claude $2 / $10, DeepSeek $0.30 / $1.20). Task A: Claude 24,121 in + 524 out, about $0.05; DeepSeek 17,104 in + 400 out, about $0.006. Task B: Claude 377,821 in + 7,838 out, about $0.83; DeepSeek 653,342 in + 7,431 out, about $0.21. Task C: Claude fails on the invalid key with no tokens used; DeepSeek finishes for 17,104 in + 400 out, about $0.006. Keys go into TrueForge through scripts/setup-providers; the extension never reads or sends one. Switching models means changing models.main / models.backup in config/moon.json, no code. Retrieval, cancel and safety evals pass on both models.

Fallback. TrueForge errors carry the provider's status code, for example [Model Error] Request failed (401). Moon switches at once on 401, 403, 404, 5xx and "Cannot connect", retries a 429 twice, and switches when nothing streams for 12 s; the same request restarts on a new session with the backup model, never stitching two half answers. A circuit breaker probes the main model through TrueForge (after 30 s, doubling up to 10 min) and moves back only between tasks. Measured: bad key 0.46 s, dead address 0.08 s, hanging server 12 s; git status clean in all five scenarios.

8  Security

Following the OWASP Top 10 for LLM Applications (2026), Moon assumes the model will be fooled, and no control asks a model to judge safety. The agent has untrusted input, the project's secrets and a shell (the "lethal trifecta"), so every change and command needs a human approval, and a task that has read outside text (web, past sessions, third-party MCP) loses network commands.

Tested: 14 attack scenarios (prompt injection, secret exfiltration, hidden Unicode, poisoned memory) pass on both models; a direct tool-server call that skips TrueForge is refused.

9  Known limitations and the next month

  • Every eval ran on Windows 11; the macOS and Linux paths (process kill, temp folders) are written but untested.
  • Retrieval misses happen: for "make the log format configurable" the agent picked docs/config.rst over docs/logging.rst in 3 of 3 runs.
  • Undo backups live in memory, so a chat resumed from history cannot undo runs it applied before.
  • Network blocking is a proxy setting, not an OS sandbox; the secret scanner uses patterns and entropy only (a classifier would need a model call).
  • Azure retires the DeepSeek V4.1 Flash preview on 15 Dec 2026; replacing it is a config change.

Next month: evals on macOS and Linux, undo backups kept with the session, JS/TS and Go repos in the retrieval evals.
